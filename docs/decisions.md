# Решения

> **Согласовано** — принято вместе. **Предложено** — вариант ассистента; подтверждаем на указанном этапе.
> Новое решение — новая запись; изменённое — меняем статус и дописываем причину, а не удаляем.

## D-01. Формат: PWA, а не нативное приложение — Согласовано

- **Решение:** веб-приложение с манифестом и service worker; на iPhone ставится через Safari → «На экран Домой».
- **Альтернативы:** Capacitor (нужны Xcode и аккаунт разработчика за $99/год для App Store); React Native / Expo (другой стек).
- **Почему:** знакомый стек, без Xcode, офлайн и полноэкранный режим доступны, Web Push на iOS есть для будущих напоминаний.
- **Ограничения iOS:** нужен HTTPS; хранилище иконки на домашнем экране отдельно от вкладки Safari; при удалении иконки данные пропадают.

## D-02. Стек: Vite + React + TypeScript — Согласовано

- **Почему:** опыт автора, быстрая сборка, `vite-plugin-pwa` закрывает PWA-часть.
- Стили: CSS Modules (`Component.module.css` рядом с компонентом), глобальные переменные и сброс — в `src/index.css`. Без UI-библиотек — минимум зависимостей. См. D-14.
- Тесты: Vitest для чистой логики (очередь прохода, подсчёт итогов).

## D-03. Направления свайпов — Согласовано

- Вправо — «помню», влево — «не помню» (привычная конвенция).
- При сдвиге карточка подсвечивается цветом; внизу дублирующие кнопки (обучаемость, доступность).

## D-04. Хранение: только на устройстве, без аккаунтов — Согласовано

- **Альтернатива:** облачная БД (Supabase и т. п.) — нужны аккаунты, лишний объём для первой пробы.
- **Следствие:** данные живут в одном браузере/устройстве. Экспорт и синхронизация — в [ideas.md](ideas.md).

## D-05. Технология хранения: IndexedDB через Dexie — Согласовано (этап 2)

- **Альтернативы:** `localStorage` — проще, но синхронный, ~5 МБ, неудобен для лога ответов; `idb` — тонкая обёртка (~1 КБ), но миграции и реактивность вручную.
- **Почему:** асинхронный, реактивные запросы (`useLiveQuery`), удобные миграции схемы.
- **Итог этапа 2:** две таблицы — `decks` (пачка целиком) и `activeSessions` (ключ — id пачки, поэтому проход у пачки один). Встроенная пачка записывается в `on('populate')` — ровно один раз при создании БД. Тесты хранилища идут в node через `fake-indexeddb`. На iPhone продолжение после закрытия Safari работает.

## D-06. Объём «прогресса» в MVP — Изменено (этап 3)

Продолжение прерванного прохода + итоги прошлых проходов + лог каждого ответа (карточка, направление, результат, был ли переворот, время). Лог — дешёвый задел для FSRS и срезов.

- **Изменение (этап 3):** история итогов прошлых проходов убрана; экран итогов в конце текущего прохода остаётся. Остаются продолжение прохода и лог ответов (формат — D-16).
- **Почему:** чем проще, тем лучше. «21 из 25 неделю назад» почти ничего не даёт и подталкивает соревноваться с прошлым результатом и к перфекционизму. Продукт должен не показывать статистику, а давать карточки для повтора по алгоритму интервалов — для него нужен только лог.

## D-07. Генерация: сначала мок за интерфейсом, потом реальный ИИ — Согласовано

- Первая пачка встроена в код. Экран создания пачки работает с мок-генератором, который умеет имитировать ошибки.
- Реальный провайдер подключается отдельным этапом без изменения UI.

## D-08. Процесс генерации: черновик с правкой — Согласовано (этап 5)

- ИИ возвращает черновик → пользователь правит / удаляет карточки → «Сохранить».
- Тот же редактор используется для правки сохранённой пачки.
- Совмещает «предварительный отбор» и «сразу готовую пачку»: без правок это один тап.
- **Уточнение (этап 5):** черновик не хранится — уход до «Сохранить» спрашивает «Выйти без сохранения?»; генерация дешёвая, повторить быстро. Подтверждения — системный `confirm`.

## D-09. Доступ к ИИ через серверную функцию — Согласовано (этап 6)

- Ключ провайдера нельзя хранить в браузере → одна функция `/api/generate` на хостинге.
- Structured output (JSON Schema) + проверка ответа на сервере и в приложении.
- Защита публичного адреса: код доступа, тема ≤100 символов, не больше 100 карточек, ограничение длины ответа модели и таймаут. Счётчиков запросов нет — бюджет держит предоплаченный баланс OpenAI без автопополнения.
- Код доступа не встроен в приложение: при отказе сервера экран ошибки показывает поле «Код доступа», код хранится в `localStorage` и уходит в заголовке `X-Access-Code`.
- **Альтернатива:** BYOK (пользователь вводит свой ключ) — без бэкенда, но не годится для других людей.
- **Итог этапа 6:** `api/generate.ts` — Web-обработчик `POST(request)`, тонкая обёртка над `handleGenerate` из `src/generation/`; там же запрос к OpenAI, проверка ответа и тесты (файл в `api/` Vercel считал бы функцией). `npm run dev` обслуживает функцию через middleware в `vite.config.ts` с ключами из `.env.local`; `VITE_GENERATOR=mock` включает мок. Находки:
  - Вместо `zod` — своя функция проверки на 40 строк: форма маленькая, strict structured output уже держит схему, проверка нужна в основном для очистки (пробелы, пустые стороны, повторы, потолок 100).
  - Код сравнивается по SHA-256 побайтно через Web Crypto, а не `node:crypto.timingSafeEqual`: модуль общий для приложения и сервера, а в типах приложения нет Node.
  - Тема — свободный запрос: число карточек ИИ берёт из него («50 слов про …»), иначе 25.
  - Первый деплой упал с `ERR_MODULE_NOT_FOUND`: Vercel компилирует каждый `.ts` функции в `.js`, но пути импорта оставляет как есть, и `import '…/generateHandler.ts'` ищет несуществующий файл. Серверные модули теперь импортируют друг друга с `.js` (Vite, Vitest и TypeScript это понимают) и не тянут ничего вне `src/generation/` — ключ склейки повторён в `validateDeck` одной строкой вместо импорта `domain/deckDraft`. Локально такое падение ловит компиляция `tsc` в `.js` и запуск в Node.

## D-10. Провайдер ИИ: OpenAI API — Согласовано (этап 6)

- **Почему:** у автора уже есть аккаунт OpenAI (ChatGPT Plus не даёт API, но аккаунт тот же); строгий structured output; пачка на лёгкой модели стоит доли цента.
- **Альтернативы:** Anthropic, Google Gemini (есть бесплатный тариф с оговорками по данным).
- **Итог этапа 6:** модель по умолчанию — `gpt-6-luna` ($0,1 / $0,5 за 1M токенов) без рассуждения (`reasoning.effort: 'none'`), Responses API через `fetch` без SDK; переопределяется `OPENAI_MODEL`. Ключ — отдельный проект «Cards» с правом только на Responses. Прогон промпта:
  - «кухня», «аэропорт», «emotions» — по 25 осмысленных карточек за 3–6 с, название по-русски («Кухня», «Эмоции»).
  - «мне нужно 50 слов EN-RU на тему путешествий» — 50 карточек за 6 с; «200 слов про еду» — ровно 100 за 17 с; «20 немецких слов про школу» — 20 карточек EN → RU.
  - «что взять в поход» давал существительные с артиклем («a tent»); правило «как в словаре: без a / an / the» это убрало.

## D-11. Хостинг: Vercel — Согласовано (этап 4)

- **Почему:** статика и серверная функция в одном проекте, бесплатный тариф, HTTPS из коробки.
- **Альтернативы:** Cloudflare Pages + Workers, Netlify.
- **Итог этапа 4:** Git-интеграция без CI. Прод — https://cards-lake-theta.vercel.app из `master`; `develop` — превью по постоянному адресу https://cards-git-develop-lelderbes-projects.vercel.app. Настройки сборки и заголовки кеширования — в `vercel.json`. Находки:
  - Vercel создаёт деплои только на пуши после подключения проекта: ветку, запушенную раньше, нужно задеплоить вручную (Deployments → Create Deployment).
  - Превью по умолчанию закрыты Vercel Authentication — установленное на iPhone приложение (свои cookies) упирается в страницу входа. Защита отключена: секретов в сборке нет.
  - Для проверки обновления нужен адрес ветки (`cards-git-develop-…`), а не адрес конкретного деплоя — тот не меняется.
  - Обновление (`autoUpdate`) на iPhone приходит со второго запуска с сетью после деплоя.

## D-12. Жесты: библиотека `motion` — Согласовано (этап 1)

- **Альтернатива:** свои Pointer Events — полезно для понимания, но дольше довести до приятного ощущения.
- **Итог этапа 1:** на iPhone свайпы, наклон, подсветка и возврат ощущаются нативно. Две находки:
  - `motion` завершает drag и по `pointercancel`; когда Safari перехватывал жест (сдвиг страницы), карточка улетала, не будучи отпущенной. Отменённый жест теперь возвращает карточку, а `touchmove` на карточке гасится через `preventDefault`; `overscroll-behavior: none` — на `html`, не на `body`.
  - Тап срабатывал в конце короткого свайпа — `onTap` игнорируется, если указатель сместился больше чем на 8px.

## D-13. Процесс: OpenSpec в лёгком режиме — Согласовано

- Продуктовые документы — в `docs/`. Каждый этап плана с изменением поведения — один change в OpenSpec (`/opsx:propose` → ревью → `/opsx:apply` → `/opsx:archive`).
- Этапы без изменения поведения (каркас, обкатка) — без change.

## D-14. Стили: CSS Modules — Согласовано

- **Решение:** один `.module.css` на компонент; цвета, отступы и темы — CSS-переменные в `src/index.css`; тёмная тема через `prefers-color-scheme`.
- **Альтернативы:** Tailwind (быстро, но разметка обрастает классами и нужна настройка); CSS-in-JS (styled-components и т. п. — рантайм и лишняя зависимость); один глобальный CSS с БЭМ (риск конфликтов имён по мере роста).
- **Почему:** работает в Vite без настройки, классы изолированы по компоненту, обычный CSS без новой нотации — легко читать и менять.

## D-15. Незавершённый проход — Согласовано (этап 2)

- **Решение:** у пачки не больше одного незавершённого прохода. Он сохраняется после каждой оценки (без оценок — не сохраняется) и продолжается кнопкой «Продолжить» на экране пачки: та же очередь, направление и счётчики «не помню», карточка лицевой стороной. «Выйти» проход не сбрасывает; «Начать заново» сразу удаляет прежний и начинает новый в выбранном направлении.
- **Срок:** до конца следующего дня (местное время) после последней оценки. Протухшие проходы удаляются при запуске приложения; пока приложение открыто, показанный проход можно продолжить.
- **Альтернативы:** бессрочный проход — недельный «хвост» с очередью под другой день; скользящие 24 часа — при занятиях «примерно вечером» проход то протухал бы, то нет; автопереход в проход при запуске — непонятно, где ты.
- **Почему:** пользователю не нужно помнить «успеть до …», а старая очередь не висит отметкой «осталось N» бесконечно. Другое направление — новый проход, а не смена режима у той же очереди.

## D-16. Лог ответов — Согласовано (этап 3)

- **Решение:** на каждый ответ (включая повторные «не помню» в одном проходе) пишется запись: `sessionId`, `deckId`, `cardId`, `direction`, `remembered`, `wasFlipped`, `answeredAt` (`Date.now()`), `durationMs` (от показа карточки до ответа).
- **Почему:** алгоритмам интервалов (FSRS и проще) нужна история ответов по каждой карточке — дата и оценка; задним числом её не восстановить. Итоги проходов алгоритму не нужны (D-06).
- `durationMs` FSRS не использует; пишем, потому что дёшево и не восстанавливается: «помню» без переворота за секунду и после долгого раздумья — разное знание (возможная градация Easy / Good / Hard без новых жестов). Значение сырое: при продолжении прохода отсчёт идёт с показа карточки; выбросы (отвлёкся, свернул приложение) отсекаются при чтении, а не при записи.
- Время до переворота не пишем — без ясной пользы.
- `sessionId` связывает ответы одного прохода; для FSRS берётся первый ответ по карточке за день — это решается при чтении.
- **Итог этапа 3:** таблица `answerLog` в схеме Dexie `version(2)`; запись ответа и сохранение / удаление незавершённого прохода — одна транзакция. Проходы версии 0.2 получают `sessionId` при обновлении схемы. Находки:
  - id создаётся через `crypto.getRandomValues`, а не `crypto.randomUUID`: последний недоступен вне secure context, т. е. на iPhone при открытии dev-сервера по HTTP в локальной сети.
  - `durationMs` считается до конца анимации вылета карточки (+0,25 с постоянной добавки) — так замер остаётся в одном месте, для сравнения ответов это не мешает.
  - Откат на 0.2 без потери данных невозможен: старый код не открывает БД версии 2.

## D-17. Карточки в общем «котле» — Согласовано (этап 5)

- **Решение:** карточка хранится один раз (таблица `cards`) и входит в пачки через список `deckIds`; пачка — название и языки, без массива карточек. Исправленный текст виден во всех пачках карточки.
- **Склейка:** новая карточка, совпавшая с существующей по паре «слово + перевод» без учёта регистра и пробелов по краям, не создаётся — существующая добавляется в пачку. Одинаковое слово с другим переводом («guide — экскурсовод» / «руководство») — разные карточки: учатся отдельно. Существующие карточки, ставшие одинаковыми после правки, не склеиваются.
- **«Все карточки»** — виртуальная пачка (id `all`, без строки в БД) со всеми карточками, включая не входящие ни в одну пачку. Её можно проходить и править; «×» в её редакторе удаляет карточку навсегда (с подтверждением), «×» в редакторе пачки — только убирает из пачки. Удаление пачки оставляет карточки во «Всех карточках».
- **Состав прохода** фиксируется при старте (`cardIds`): добавленные позже карточки в проход не входят, удалённые выпадают; правка пачки проход не сбрасывает.
- **Альтернативы:** карточки внутри пачки — одно слово в двух пачках стало бы двумя карточками с двумя расписаниями повторов; теги вместо пачек — то же хранение, другой интерфейс, два понятия вместо одного; удалять карточки без пачки — тихая потеря данных; пачка «Без пачки» — полезна только вместе с перемещением карточек (см. [ideas.md](ideas.md)).
- **Почему:** будущие интервальные повторения ведут расписание по карточке, а не по пачке; повторять удобнее поверх пачек («К повторению»), и снимок состава прохода нужен такой пачке, чей состав меняется со временем.
- **Итог этапа 5:** схема Dexie `version(3)` — таблица `cards` (`id, *deckIds`), у пачек и карточек `createdAt` (порядок списка и карточек), у прохода `cardIds`; миграция переносит карточки и незавершённые проходы. Склейка и план записи — чистые функции в `src/domain/deckDraft.ts`; генератор — `src/generation/`, мок подключён в `generateDeck.ts`. На iPhone обновление с 0.4 сохранило пачку и проход. Находки:
  - Проход хранит состав, а хранилище при правке проходы не трогает: согласование — в `restoreSession` при чтении, и список считает «осталось N» тоже через неё — иначе после удаления карточки список и экран пачки расходились бы.
  - Пачка может опустеть, если её карточки удалены навсегда во «Всех карточках»: экран пачки тогда показывает «В пачке нет карточек» вместо «Начать».
  - Системный `confirm` в установленном приложении на iPhone выглядит уместно; своя модалка не понадобилась. При автоматической проверке в браузере (Claude in Chrome) `confirm` блокирует управление страницей — на время проверки его подменяли.
  - Подключение генератора вынесено из `generator.ts` в `generateDeck.ts`, чтобы мок и интерфейс не импортировали друг друга по кругу.
  - Откат на 0.4 без потери данных невозможен: старый код не открывает БД версии 3.
