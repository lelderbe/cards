# Решения

> **Согласовано** — принято вместе. **Предложено** — вариант ассистента; подтверждаем на указанном этапе.
> Новое решение — новая запись; изменённое — меняем статус и дописываем причину, а не удаляем.

## D-01. Формат: PWA, а не нативное приложение — Согласовано

- **Решение:** веб-приложение с манифестом и service worker; на iPhone ставится через Safari → «На экран Домой».
- **Альтернативы:** Capacitor (нужны Xcode и аккаунт разработчика за $99/год для App Store); React Native / Expo (другой стек).
- **Почему:** знакомый стек, без Xcode, офлайн и полноэкранный режим доступны, Web Push на iOS есть для будущих напоминаний.
- **Ограничения iOS:** нужен HTTPS; хранилище иконки на домашнем экране отдельно от вкладки Safari; при удалении иконки данные пропадают.

## D-02. Стек: Vite + React + TypeScript — Согласовано

- **Почему:** опыт автора, быстрая сборка, `vite-plugin-pwa` закрывает PWA-часть.
- Стили: CSS Modules (`Component.module.css` рядом с компонентом), глобальные переменные и сброс — в `src/index.css`. Без UI-библиотек — минимум зависимостей. См. D-14.
- Тесты: Vitest для чистой логики (очередь прохода, подсчёт итогов).

## D-03. Направления свайпов — Согласовано

- Вправо — «помню», влево — «не помню» (привычная конвенция).
- При сдвиге карточка подсвечивается цветом; внизу дублирующие кнопки (обучаемость, доступность).

## D-04. Хранение: только на устройстве, без аккаунтов — Согласовано

- **Альтернатива:** облачная БД (Supabase и т. п.) — нужны аккаунты, лишний объём для первой пробы.
- **Следствие:** данные живут в одном браузере/устройстве. Экспорт и синхронизация — в [ideas.md](ideas.md).

## D-05. Технология хранения: IndexedDB через Dexie — Согласовано (этап 2)

- **Альтернативы:** `localStorage` — проще, но синхронный, ~5 МБ, неудобен для лога ответов; `idb` — тонкая обёртка (~1 КБ), но миграции и реактивность вручную.
- **Почему:** асинхронный, реактивные запросы (`useLiveQuery`), удобные миграции схемы.
- **Итог этапа 2:** две таблицы — `decks` (пачка целиком) и `activeSessions` (ключ — id пачки, поэтому проход у пачки один). Встроенная пачка записывается в `on('populate')` — ровно один раз при создании БД. Тесты хранилища идут в node через `fake-indexeddb`. На iPhone продолжение после закрытия Safari работает.

## D-06. Объём «прогресса» в MVP — Согласовано

Продолжение прерванного прохода + итоги прошлых проходов + лог каждого ответа (карточка, направление, результат, был ли переворот, время). Лог — дешёвый задел для FSRS и срезов.

## D-07. Генерация: сначала мок за интерфейсом, потом реальный ИИ — Согласовано

- Первая пачка встроена в код. Экран создания пачки работает с мок-генератором, который умеет имитировать ошибки.
- Реальный провайдер подключается отдельным этапом без изменения UI.

## D-08. Процесс генерации: черновик с правкой — Предложено (подтвердить на этапе 4)

- ИИ возвращает черновик → пользователь правит / удаляет карточки → «Сохранить».
- Тот же редактор используется для правки сохранённой пачки.
- Совмещает «предварительный отбор» и «сразу готовую пачку»: без правок это один тап.

## D-09. Доступ к ИИ через серверную функцию — Предложено (подтвердить на этапе 5)

- Ключ провайдера нельзя хранить в браузере → одна функция `/api/generate` на хостинге.
- Structured output (JSON Schema) + проверка ответа (`zod`).
- Защита публичного адреса: код доступа и лимит карточек на запрос.
- **Альтернатива:** BYOK (пользователь вводит свой ключ) — без бэкенда, но не годится для других людей.

## D-10. Провайдер ИИ: OpenAI API — Предложено (подтвердить на этапе 5)

- **Почему:** у автора уже есть аккаунт OpenAI (ChatGPT Plus не даёт API, но аккаунт тот же); строгий structured output; пачка на лёгкой модели стоит доли цента, $5 хватит надолго.
- **Альтернативы:** Anthropic, Google Gemini (есть бесплатный тариф с оговорками по данным).

## D-11. Хостинг: Vercel — Предложено (подтвердить на этапе 3)

- **Почему:** статика и серверная функция в одном проекте, бесплатный тариф, HTTPS из коробки.
- **Альтернативы:** Cloudflare Pages + Workers, Netlify.

## D-12. Жесты: библиотека `motion` — Согласовано (этап 1)

- **Альтернатива:** свои Pointer Events — полезно для понимания, но дольше довести до приятного ощущения.
- **Итог этапа 1:** на iPhone свайпы, наклон, подсветка и возврат ощущаются нативно. Две находки:
  - `motion` завершает drag и по `pointercancel`; когда Safari перехватывал жест (сдвиг страницы), карточка улетала, не будучи отпущенной. Отменённый жест теперь возвращает карточку, а `touchmove` на карточке гасится через `preventDefault`; `overscroll-behavior: none` — на `html`, не на `body`.
  - Тап срабатывал в конце короткого свайпа — `onTap` игнорируется, если указатель сместился больше чем на 8px.

## D-13. Процесс: OpenSpec в лёгком режиме — Согласовано

- Продуктовые документы — в `docs/`. Каждый этап плана с изменением поведения — один change в OpenSpec (`/opsx:propose` → ревью → `/opsx:apply` → `/opsx:archive`).
- Этапы без изменения поведения (каркас, обкатка) — без change.

## D-14. Стили: CSS Modules — Согласовано

- **Решение:** один `.module.css` на компонент; цвета, отступы и темы — CSS-переменные в `src/index.css`; тёмная тема через `prefers-color-scheme`.
- **Альтернативы:** Tailwind (быстро, но разметка обрастает классами и нужна настройка); CSS-in-JS (styled-components и т. п. — рантайм и лишняя зависимость); один глобальный CSS с БЭМ (риск конфликтов имён по мере роста).
- **Почему:** работает в Vite без настройки, классы изолированы по компоненту, обычный CSS без новой нотации — легко читать и менять.

## D-15. Незавершённый проход — Согласовано (этап 2)

- **Решение:** у пачки не больше одного незавершённого прохода. Он сохраняется после каждой оценки (без оценок — не сохраняется) и продолжается кнопкой «Продолжить» на экране пачки: та же очередь, направление и счётчики «не помню», карточка лицевой стороной. «Выйти» проход не сбрасывает; «Начать заново» сразу удаляет прежний и начинает новый в выбранном направлении.
- **Срок:** до конца следующего дня (местное время) после последней оценки. Протухшие проходы удаляются при запуске приложения; пока приложение открыто, показанный проход можно продолжить.
- **Альтернативы:** бессрочный проход — недельный «хвост» с очередью под другой день; скользящие 24 часа — при занятиях «примерно вечером» проход то протухал бы, то нет; автопереход в проход при запуске — непонятно, где ты.
- **Почему:** пользователю не нужно помнить «успеть до …», а старая очередь не висит отметкой «осталось N» бесконечно. Другое направление — новый проход, а не смена режима у той же очереди.
