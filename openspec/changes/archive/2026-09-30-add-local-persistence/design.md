# Design

## Context

После этапа 1: `App` держит `screen: 'start' | 'study' | 'results'`, пачка импортируется из `src/data/starterDeck.ts`, проход — чистый редьюсер `studySession` (состояние `StudySession` — простой JSON: `direction`, `queue`, `isFlipped`, `forgotCounts`, `totalCards`). `StudyScreen` держит сессию в локальном `useState` и отдаёт наверх только при завершении. Хранилища нет. Тесты — Vitest в node-окружении, без DOM.

Решения по развилкам (зафиксированы в proposal / specs): «Выйти» ведёт на экран пачки с сохранённым проходом; продолжение — кнопкой на экране пачки, а не автопереходом; проход живёт до конца следующего дня после последней оценки; без роутера; хранилище — Dexie (D-05).

## Goals / Non-Goals

**Goals:**
- Слой хранения отделён от домена: `src/domain/` не импортирует Dexie; восстановление прохода и расчёт его срока — чистые функции с тестами.
- Схема БД, которую этапы 3 и 5 расширяют новой версией Dexie, без переписывания текущих таблиц.
- Тесты хранилища без браузера (`fake-indexeddb`).

**Non-Goals:**
- Оптимистичные обновления, очереди записи, обработка конфликтов между вкладками.
- Таймеры и перепроверка срока прохода, пока приложение открыто.
- Отдельная таблица карточек (нужна будет, только если лог/интервалы начнут ссылаться на карточки запросами — этап 3 решит).

## Decisions

### 1. Схема БД: две таблицы

```ts
// src/storage/db.ts
class CardsDb extends Dexie {
  decks!: Table<Deck, string>                  // 'id, title'
  activeSessions!: Table<SavedSession, string> // 'deckId'
}
type SavedSession = { deckId: string; session: StudySession; lastAnsweredAt: number }
```

- Пачка хранится целиком, вместе с массивом `cards` — одна запись на пачку. Пачку всегда читают и (на этапе 5) правят целиком; размер пачки не ограничен, но сотня карточек — это десятки килобайт, запись одной строкой остаётся дешёвой.
- `activeSessions` с ключом `deckId` сам обеспечивает «не больше одного незавершённого прохода на пачку»: `put` заменяет прежний.
- `StudySession` хранится как есть: он уже сериализуем (строки, числа, объект-словарь). `lastAnsweredAt` — `Date.now()` момента записи, по нему считается срок.

Альтернативы: одна таблица с полем `activeSession` внутри пачки — смешивает редкие правки пачки с записью на каждый свайп; отдельная таблица `cards` — лишние join-и сейчас.

### 2. Первичное заполнение — `db.on('populate')`

Dexie вызывает `populate` ровно один раз — при создании БД. В нём `decks.add(starterDeck)`. Флаг «уже заполняли» не нужен; когда на этапе 5 появится удаление пачек, удалённая встроенная пачка не вернётся при следующем запуске.

Альтернатива: «если `decks` пуст — добавить стартовую» — вернула бы пачку после удаления всех пачек и гонялась бы при двух одновременных открытиях.

### 3. Репозиторий — тонкие async-функции

`src/storage/decks.ts`: `getDeck(id)`; `src/storage/sessions.ts`: `saveActiveSession(deckId, session, now)`, `getActiveSession(deckId)`, `deleteActiveSession(deckId)`, `deleteExpiredSessions(now)`. Экраны читают данные через `useLiveQuery` из `dexie-react-hooks` — список и экран пачки сами обновляются после записи прохода, без ручной перезагрузки состояния в `App`.

`db` экспортируется как синглтон; тесты импортируют `fake-indexeddb/auto` до создания БД и чистят таблицы в `beforeEach`.

### 4. Восстановление прохода — чистая функция в домене

```ts
restoreSession(saved: StudySession, deck: Deck): StudySession | undefined
```

- Сбрасывает `isFlipped` → карточка показывается лицевой стороной (спека «Продолжение прохода»).
- Выкидывает из `queue` id, которых больше нет в пачке, и чистит `forgotCounts` от них; `totalCards` пересчитывает по пачке. Сейчас пачки не меняются, но с этапа 5 редактор может удалить карточку посреди прохода — страховка дешёвая.
- Пустая очередь после фильтрации → `undefined` (проход считается несуществующим).

Функция живёт в `src/domain/studySession.ts` и тестируется как остальной редьюсер.

### 5. Срок прохода — «до конца следующего дня»

```ts
// src/domain/sessionExpiry.ts
getSessionExpiry(lastAnsweredAt: number): number // начало послезавтрашнего дня по местному времени
isSessionFresh(lastAnsweredAt: number, now: number): boolean // now < getSessionExpiry(lastAnsweredAt)
```

- Граница считается через `Date`: `new Date(lastAnsweredAt)`, `setHours(0, 0, 0, 0)`, `setDate(date + 2)`. Календарная арифметика, а не `+ 48 * 3600_000`, поэтому переход на летнее / зимнее время не сдвигает границу с полуночи.
- Пользователю не нужно помнить «успеть до 21:37»: ответил когда угодно сегодня — завтра весь день можно продолжить.
- `now` передаётся параметром (как `random` в `createSession`) → граничные случаи — обычные юнит-тесты.

Альтернатива: скользящие 24 часа — при занятиях «примерно вечером» проход то протухал бы, то нет, в зависимости от минут.

### 6. Когда пишем и удаляем проход

- **После каждой оценки:** `StudyScreen` получает колбэк `onProgress(session)`, `App` вызывает `saveActiveSession(deckId, session, Date.now())`. Запись не блокирует UI (без `await` в обработчике), ошибка пишется в консоль — потеря одного сохранения не ломает текущий проход.
- **При старте прохода — не пишем:** проход без оценок нечего терять. Запись появляется с первой оценкой.
- **«Начать заново»** — сразу `deleteActiveSession(deckId)`, затем новый проход. Выход до первой оценки оставляет пачку без прохода (спека «Начать заново»).
- **Переворот** не сохраняется — `isFlipped` всё равно сбрасывается при восстановлении.
- **Завершение** — `deleteActiveSession`, затем экран итогов (итоги берутся из сессии в памяти).
- **«Выйти»** ничего не пишет (последняя оценка уже сохранена) и открывает экран пачки.
- **Протухшие проходы** — `deleteExpiredSessions(Date.now())` один раз при старте `App`, после открытия БД и до показа списка. Экраны срок не проверяют: что показано — то можно продолжить; очередная оценка обновит `lastAnsweredAt`.

Альтернатива: сохранять по `visibilitychange` / `pagehide` — на iOS эти события при выгрузке PWA ненадёжны; запись на каждый ответ проще и надёжнее.

### 7. Экраны и навигация без роутера

```ts
type AppState =
  | { screen: 'decks' }
  | { screen: 'deck'; deckId: string }
  | { screen: 'study'; deckId: string; session: StudySession; sessionNumber: number }
  | { screen: 'results'; deckId: string; session: StudySession }
```

- `DeckListScreen` — `useLiveQuery` по `decks` и `activeSessions`; отметка «осталось N» = `session.queue.length`.
- `DeckScreen` (бывший `StartScreen`) — читает пачку и её активный проход. Без прохода — «Начать». С проходом — главная «Продолжить» (подпись «EN → RU · осталось N») и второстепенная «Начать заново». Переключатель направления инициализируется направлением прохода, если он есть, иначе последним выбранным в `App`; «Продолжить» его не читает. «Продолжить» использует `restoreSession`; если он вернул `undefined`, экран ведёт себя как «нет прохода».
- `StudyScreen` и `ResultsScreen` получают пачку пропсом, как сейчас; `App` загружает её при переходе. Кнопка «На старт» → «К пачке».
- Пока `useLiveQuery` возвращает `undefined` или идёт стартовая очистка — заглушка загрузки. Ошибку открытия БД ловим через `db.open().catch` при старте `App`, храним в состоянии и показываем сообщение.

Роутер не нужен: в standalone-режиме нет адресной строки и кнопки «назад», а экранов четыре в одной линии.

### 8. Запрос постоянного хранилища

При старте вызываем `navigator.storage?.persist?.()` без ожидания результата и без UI. Это просьба к браузеру не вытеснять данные при нехватке места; для иконки на домашнем экране iOS и так не применяет 7-дневную очистку, но во вкладке Safari это помогает.

## Risks / Trade-offs

- [Safari во вкладке удаляет данные сайта после 7 дней без посещений] → основной режим — иконка на домашнем экране (этап 4), где правило не действует; плюс `persist()`. Экспорт — в ideas.md.
- [Хранилище вкладки Safari и иконки на домашнем экране разные (D-01)] → пачка при первом запуске иконки заполнится заново, незавершённый проход из вкладки туда не перейдёт. Ожидаемо, фиксируем в проверке этапа.
- [iOS может выгрузить свёрнутую PWA и перезапустить её при возврате] → для пользователя это «запуск»: протухший проход исчезнет. Совпадает с намерением — срок проверяется при запуске.
- [Перелёт через часовые пояса или ручная смена часов] → граница «конец следующего дня» считается по текущему поясу устройства и может сдвинуться на несколько часов; приемлемо.
- [Запись на каждый свайп] → одна маленькая запись `put` на ответ; для IndexedDB это незаметно.
- [Сохранение не успело перед закрытием] → теряется максимум одна последняя оценка; приемлемо.
- [Размер бандла: dexie ~25 КБ gzip + dexie-react-hooks ~1 КБ] → приемлемо, D-05 это и предполагало.

## Migration Plan

Данных у пользователей ещё нет — это первая версия схемы (`db.version(1)`). Будущие изменения — новыми `db.version(n)` с `upgrade`. Откат: удалить БД через DevTools (приложение заполнит её заново).
