# Design

## Context

Каркас этапа 0: Vite + React 19 + TS, `vite-plugin-pwa`, Vitest, oxlint, пустой `App`. Хранения нет — всё состояние живёт в памяти до перезагрузки. Целевое устройство — iPhone в портретной ориентации, в том числе в режиме «с экрана Домой».

## Goals / Non-Goals

**Goals:**
- Логика прохода — чистые функции без React, полностью покрытые тестами.
- Жест ощущается «как в нативном приложении»: карточка идёт за пальцем, наклоняется, подсвечивается и улетает.
- Структура, которую этапы 2–3 расширят без переписывания: модель данных уже с `id`, логика не знает об источнике пачки.

**Non-Goals:**
- Роутер, глобальный стейт-менеджер, UI-библиотека.
- Анимации сверх необходимых (переворот, свайп, возврат).

## Decisions

### 1. Модель данных: нейтральные `front` / `back`

```ts
type Card = { id: string; front: string; back: string }
type Deck = { id: string; title: string; frontLang: 'en'; backLang: 'ru'; cards: Card[] }
type Direction = 'front-to-back' | 'back-to-front'
```

Поля не называются `en` / `ru`, чтобы другие языки и термины из ideas.md не требовали миграции. Направление — union-тип, без enum.

### 2. Логика прохода — чистый редьюсер `studySession`

Состояние: `queue: string[]` (id карточек, голова — текущая), `isFlipped`, `forgotCounts: Record<string, number>`, `totalCards`, `direction`.
Действия: `flip`, `answer(remembered: boolean)`. Функции `createSession(deck, direction, random)` и `getResults(session, deck)`.

- `random` передаётся параметром (по умолчанию `Math.random`) → перемешивание Фишера–Йетса детерминировано в тестах.
- «Не помню» перемещает голову в хвост (одна карточка → остаётся той же), «помню» — удаляет голову; оба сбрасывают `isFlipped`.
- Проход завершён, когда `queue` пуст.

Альтернативы: Zustand / Redux — избыточно для состояния одного экрана; логика прямо в компоненте — не тестируется без рендера. `useReducer` + чистые функции — минимально и тестируемо. На этапе 2 это же состояние сериализуется в IndexedDB как есть.

### 3. Экраны без роутера

`App` хранит `screen: 'start' | 'study' | 'results'` и текущую сессию. Три экрана — один линейный сценарий, URL ему не нужен. Роутер появится на этапе 2 вместе со списком пачек; компоненты экранов при этом не меняются, меняется только место их монтирования.

### 4. Жест — `motion`

`motion.div` с `drag="x"`, позиция в `useMotionValue(x)`; и возврат, и улёт делаются явным `animate(x, …)` в `onDragEnd`, чтобы автоматический snap не спорил с анимацией улёта. Через `useTransform(x)` вычисляются наклон (±12°) и прозрачность цветовых подсказок («Помню» — зелёная справа, «Не помню» — красная слева).
`onDragEnd`: оценка ставится, если `|offset.x| > 30% ширины карточки` или `|velocity.x| > 500 px/s` в ту же сторону; иначе карточка возвращается. При срабатывании карточка анимированно улетает за край экрана, затем диспатчится `answer`.
Кнопки запускают ту же анимацию улёта — одна функция `handleAnswer(remembered)`, чтобы поведение не расходилось.

Альтернатива: собственные Pointer Events — меньше зависимостей (~30 КБ gzip у motion), но пружинный возврат, инерция и отмена анимаций заняли бы заметно больше кода.

### 5. Переворот — CSS 3D

Две грани с `backface-visibility: hidden`, контейнер поворачивается `rotateY(180deg)` по классу. Анимация переворота не зависит от жеста (переворот — на внутреннем элементе, свайп — на внешнем), поэтому они не конфликтуют. При `prefers-reduced-motion` переворот мгновенный.

### 6. Тап vs свайп

Тап обрабатывается через `onTap` motion-элемента: он не срабатывает, если указатель сместился за порог перетаскивания. На карточке `touch-action: none` и `user-select: none`, чтобы Safari не прокручивал страницу и не выделял текст.

### 7. Стили — CSS Modules

Один `.module.css` на компонент; общие цвета — CSS-переменные из `index.css`. Высота экрана — `100svh`, отступы — `env(safe-area-inset-*)`.

### 8. Стартовая пачка

`src/data/starterDeck.ts`, тема «Путешествия», 25 слов общеупотребительной лексики. Файл — единственное место, откуда экран получает пачку; на этапе 2 его заменит чтение из IndexedDB (с первичным заполнением этой же пачкой).

## Risks / Trade-offs

- [Системный свайп «назад» от края экрана во вкладке Safari] → карточка не доходит до краёв (горизонтальные поля ≥ 16px); основная проверка — в режиме «с экрана Домой», где этого жеста нет.
- [Случайный тап в конце короткого свайпа переворачивает карточку] → полагаемся на порог перетаскивания motion; если на iPhone это мешает — добавим проверку смещения в `onTap`.
- [Размер бандла +~30 КБ gzip] → приемлемо для PWA с кешем; при необходимости позже `LazyMotion`.
- [Прогресс теряется при перезагрузке] → осознанно, хранение — этап 2.
