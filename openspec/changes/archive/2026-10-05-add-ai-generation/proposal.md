# Proposal

## Why

Экран создания пачки (этап 5) работает на моке: для любой темы он возвращает одни и те же слова про кухню. Чтобы приложением можно было пользоваться по-настоящему, пачку по теме должен составлять ИИ. Ключ провайдера нельзя держать в браузере, поэтому нужна серверная функция, а её публичный адрес — защитить от чужих запросов. Этап 6 из [docs/plan.md](../../../docs/plan.md).

## What Changes

- **Серверная функция `/api/generate`** на Vercel (подтверждает D-09): принимает тему — свободный запрос вроде «путешествия» или «50 слов про путешествия», — запрашивает OpenAI (подтверждает D-10) со structured output по JSON Schema и возвращает пачку в том же виде, что генератор сейчас: название и карточки «английское слово — русский перевод».
- **Проверка ответа ИИ** на сервере: обрезка пробелов, отбрасывание пустых и повторяющихся карточек, не больше 100 карточек; ответ без карточек — сбой генерации.
- **Простые лимиты:** тема — непустая, не длиннее 100 символов; не больше 100 карточек; ограничение длины ответа модели и время ожидания. Бюджет держит лимит расходов в кабинете OpenAI — счётчиков запросов на сервере нет.
- **Код доступа:** функция отвечает только на запросы с верным кодом. Код не встроен в приложение: если сервер ответил «нет кода» или «неверный код», вместо обычного сообщения об ошибке появляется поле «Код доступа» и «Повторить». Принятый код хранится на устройстве и дальше не спрашивается.
- **Реальный генератор** в приложении заменяет мок: запрос к `/api/generate`, отмена через «Отмена», различение «нет сети» / «не удалось составить» / «нужен код».
- Число карточек ИИ берёт из запроса, если оно указано («50 слов про …»), иначе 20–30; потолок — 100. Подсказка в поле темы показывает такой пример.
- Название пачки придумывает ИИ (короткое, по-русски), а не берётся из темы с заглавной буквы.
- **Мок остаётся для разработки:** включается переменной окружения при `npm run dev`, чтобы проверять загрузку и ошибки без запросов к OpenAI. В обычном `npm run dev` функция `/api/generate` работает прямо в dev-сервере с ключом из `.env.local`.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `deck-generation`: генерацию выполняет ИИ через серверную функцию; ошибки генерации дополняются кодом доступа; новые требования к коду доступа и к серверной функции (лимиты, проверка ответа); мок — только для разработки.

## Non-goals

- Счётчики запросов в день и другие лимиты с хранилищем на сервере (Upstash / Vercel KV).
- Экран настроек, смена или сброс кода доступа вне сценария ошибки; разные коды для разных людей.
- Выбор языковой пары (всегда EN → RU, даже если запрос просит другое), отдельное поле числа карточек, выбор модели в интерфейсе.
- Потоковый вывод карточек по мере генерации.
- Перегенерация одной карточки, дополнение пачки, пример употребления — см. [docs/ideas.md](../../../docs/ideas.md).
- Учёт уже существующих карточек при генерации (не предлагать известные слова).
- Работа генерации офлайн.

## Impact

- Новая папка `api/` в корне — серверная функция Vercel (`api/generate.ts`); переменные окружения на Vercel: ключ OpenAI, код доступа, (необязательно) модель.
- `src/generation/`: реальный генератор, чистые функции разбора и проверки ответа ИИ и запроса к нему, новый вид ошибки `unauthorized`; `generateDeck.ts` выбирает реальный генератор или мок.
- `CreateDeckScreen`: поле кода доступа на экране ошибки; код хранится в `localStorage`.
- `vite.config.ts`: dev-middleware для `/api/generate`; `tsconfig` — проверка типов папки `api/`.
- Зависимости: без новых — запрос к OpenAI через `fetch`, проверка ответа — своя функция вместо `zod` (уточняет D-09).
- Документы: D-09 и D-10 → «Согласовано» с итогом этапа, статус этапа 6 в `docs/plan.md`, `README.md` — переменные окружения и локальный запуск.
