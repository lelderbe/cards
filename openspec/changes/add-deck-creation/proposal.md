# Proposal

## Why

Сейчас в приложении одна встроенная пачка, а сценарий MVP начинается с «выбрать тему → получить пачку». Нужен путь создания пачки по теме и правки карточек — сначала с мок-генератором за общим интерфейсом (D-07), чтобы отладить UI, загрузку и ошибки до подключения ИИ. Этап 5 из [docs/plan.md](../../../docs/plan.md).

Пачки, созданные пользователем, будут пересекаться по словам («airport» — и в «Путешествиях», и в «Зданиях»), а будущие интервальные повторения ведут расписание по карточке, а не по пачке. Поэтому до появления пользовательских пачек карточки переходят в общий «котёл»: карточка хранится один раз и может входить в несколько пачек.

## What Changes

- **Котёл карточек.** Карточка хранится один раз и может входить в несколько пачек; исправленный текст виден во всех её пачках. Встроенная пачка и незавершённые проходы переносятся в новую модель при обновлении без потерь.
- На списке пачек — кнопка «Создать пачку». Экран создания: поле темы → «Составить» → состояние загрузки с «Отменой» → черновик пачки в редакторе.
- Генерация пачки идёт через интерфейс генератора; на этом этапе за ним стоит мок: задержка около 1,5 с, 20–30 карточек, название — из темы. Ошибки мок имитирует по ключевому слову в теме: «ошибка» → генерация не удалась, «сеть» → нет подключения.
- Ошибка генерации показывается понятным сообщением с «Повторить» (та же тема) и «Изменить тему».
- **Редактор пачки** — один для черновика и для сохранённой пачки (подтверждает D-08): название, правка обеих сторон карточек, «×» у карточки, «Добавить карточку», «Сохранить» и «Отмена». Сохранение недоступно, пока у пачки нет названия или карточек либо у карточки заполнена только одна сторона; полностью пустые карточки при сохранении отбрасываются.
- **Склейка совпадений.** Новая карточка, совпавшая с уже существующей по паре «слово + перевод» (без учёта регистра и пробелов по краям), не создаётся заново — существующая карточка добавляется в пачку.
- Черновик не хранится: уход из редактора с несохранёнными правками (а из черновика — всегда) спрашивает «Выйти без сохранения?».
- После сохранения новой пачки открывается её экран — можно сразу «Начать».
- На экране пачки — «Изменить». В пачке «×» убирает карточку из пачки; сама карточка остаётся. В редакторе сохранённой пачки — «Удалить пачку» с подтверждением; карточки при этом остаются, удаляется незавершённый проход пачки, лог ответов остаётся.
- **Виртуальная пачка «Все карточки»** — первая строка списка: все карточки, включая не входящие ни в одну пачку. Её можно проходить и править; в её редакторе «×» удаляет карточку навсегда, с подтверждением при сохранении.
- **Состав прохода фиксируется при старте:** карточки, добавленные позже, в текущий проход не входят; удалённые и убранные из пачки — выпадают из очереди и итогов.

## Capabilities

### New Capabilities
- `deck-generation`: создание пачки по теме через интерфейс генератора — ввод темы, загрузка и отмена, ошибки с «Повторить», мок-генератор.
- `deck-editor`: редактор пачки и «Всех карточек» — правка, проверка и склейка при сохранении, выход без сохранения, убрать из пачки / удалить навсегда, удаление пачки.

### Modified Capabilities
- `deck-library`: карточки хранятся один раз и входят в несколько пачек; список получает «Создать пачку», «Все карточки» и порядок создания; экран пачки — «Изменить».
- `study-session`: состав прохода фиксируется при старте; правка пачки посреди прохода его не сбрасывает.

## Non-goals

- Реальный ИИ, серверная функция, код доступа и лимиты — этап 6.
- Сохранение черновика между запусками приложения.
- Выбор языковой пары и числа карточек: пара всегда EN / RU, число решает генератор.
- Пачка «Без пачки» и перемещение / добавление существующих карточек в другую пачку — см. [docs/ideas.md](../../../docs/ideas.md).
- Повторение поверх пачек («К повторению») и интервалы.
- Склейка карточек, ставших одинаковыми после правки текста: склеиваются только новые карточки.
- Показ в черновике, что карточка уже есть в другой пачке.
- Перегенерация одной карточки, дополнение пачки генератором, пример употребления.
- Отмена удаления (undo), сортировка и перестановка карточек.
- Вывод мока из продакшен-сборки: мок заменяется реальным генератором на этапе 6.

## Impact

- Схема БД: `version(3)` — новая таблица `cards` с индексом по пачкам, пачка без массива карточек, у пачек время создания, у незавершённых проходов — состав. Миграция переносит встроенную пачку и проходы; откат на 0.4.0 без потери данных невозможен.
- Новый слой `src/generation/`: тип генератора, ошибки генерации, мок. Новых зависимостей нет.
- Домен: чистые функции черновика, проверки и склейки, состав прохода в `studySession` — с тестами.
- Хранилище: сборка пачки из карточек, сохранение новой и изменённой пачки, правка «Всех карточек», удаление пачки — в `src/storage/`.
- Экраны: новые `CreateDeckScreen`, `EditDeckScreen` и компонент `DeckEditor`; изменения в `App`, `DeckListScreen`, `DeckScreen`.
- Документы: D-08 → «Согласовано», новая запись о модели котла, итог этапа в `docs/decisions.md` и `docs/plan.md`, отложенные идеи в `docs/ideas.md`.
