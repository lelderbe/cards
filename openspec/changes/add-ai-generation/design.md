# Design

## Context

После этапа 5 экран `CreateDeckScreen` вызывает `generateDeck(topic, signal)` из `src/generation/generateDeck.ts`, сейчас это мок. Интерфейс `DeckGenerator` возвращает `GeneratedDeck` (`title`, `cards: {front, back}[]`) или отклоняется `GenerationError` с `kind: 'network' | 'failed'` либо `AbortError`. Экран ошибки — `StatusMessage` с текстом по `kind` и кнопками «Повторить» / «Изменить тему». Черновик собирает `draftFromGenerated`, склейку с существующими карточками делает сохранение — генератору о котле знать не нужно.

Хостинг — Vercel (D-11): сборка Vite, Git-интеграция, `master` → прод, `develop` → превью по постоянному адресу. Серверного кода пока нет; `tsconfig.app.json` проверяет `src/`, `tsconfig.node.json` — `vite.config.ts`. PWA (`vite-plugin-pwa`, `autoUpdate`) кеширует статику; POST-запросы service worker не перехватывает.

Решения с пользователем перед этапом: провайдер — OpenAI (D-10); код доступа спрашивается на экране ошибки и хранится на устройстве; лимиты только простые, бюджет держит лимит расходов в кабинете OpenAI.

## Goals / Non-Goals

**Goals:**
- Реальная генерация без изменений экранов, кроме поля кода доступа на экране ошибки (D-07).
- Ключ OpenAI и код доступа — только в переменных окружения сервера.
- Логика запроса к ИИ, разбора и проверки ответа — чистые функции с тестами; сеть подменяется в тестах.
- `npm run dev` по-прежнему достаточно для работы, без Vercel CLI.
- Без новых зависимостей.

**Non-Goals:**
- Счётчики запросов, хранилище на сервере, разные коды для разных людей.
- Потоковый ответ, повторные попытки на сервере, выбор модели в интерфейсе.
- Автотесты самой функции против настоящего OpenAI.

## Decisions

### 1. Функция Vercel `api/generate.ts` с Web-обработчиком

```ts
// api/generate.ts
export async function POST(request: Request): Promise<Response>
```

- Папка `api/` в корне — штатный способ Vercel для не-Next проектов; сигнатура `Request → Response` без `@vercel/node`. Обработчик тонкий: читает переменные окружения и тело, проверяет код и тему, вызывает `generateWithOpenAI`, переводит результат в HTTP-ответ.
- Ответы: `200` — `{ title, cards }`; `400` — неверная тема или тело; `401` — `{ error: 'missing_code' | 'wrong_code' }`; `502` — ИИ вернул ответ не по формату или без карточек; `504` — таймаут; `500` — сервер не настроен (нет ключа или кода). Тексты для пользователя формирует приложение, сервер отдаёт только коды.
- `maxDuration` функции — 60 с через `functions` в `vercel.json` (у Hobby с Fluid compute предел 300 с), чтобы зависший запрос не съедал лимиты бесплатного тарифа.
- **Альтернатива:** Edge-функция — быстрее холодный старт, но ограничения времени и окружения; для одного запроса в минуту выигрыш незаметен.

### 2. Общая логика — в `src/generation/`, сервер её импортирует

- `src/generation/openaiDeck.ts`: `buildDeckRequest(topic, model)` — тело запроса к OpenAI Responses API (`POST /v1/responses`, `text.format: { type: 'json_schema', strict: true, schema }`), `parseDeckResponse(json)` — достаёт текст ответа и проверяет его, `generateWithOpenAI({ apiKey, model, topic, signal, fetch })` — `fetch` к OpenAI с `AbortSignal.timeout(55_000)`.
- `src/generation/validateDeck.ts`: `validateGeneratedDeck(value: unknown): GeneratedDeck | null` — своя проверка формы вместо `zod` (уточнение D-09): объект, `title` — непустая строка, `cards` — массив `{front, back}` строк; обрезка пробелов, отброс карточек с пустой стороной и повторов по паре без учёта регистра, не больше 100. Пустой результат → `null` (сбой).
- `validateTopic(topic: unknown): string | null` — обрезанная тема 1–100 символов. Константы `MAX_TOPIC_LENGTH = 100`, `MAX_CARDS = 100` — в одном модуле; экран создания берёт `MAX_TOPIC_LENGTH` оттуда же.
- Функции чистые или получают `fetch` параметром — тесты в vitest без сети.
- **Почему не `zod`:** форма ответа маленькая (две строки в массиве), strict structured output уже гарантирует схему, а проверка нужна в основном для очистки — 30 строк своего кода проще новой зависимости. **Почему не SDK `openai`:** один `fetch` с JSON, SDK не нужен.

### 3. Модель и промпт

- Модель — из `OPENAI_MODEL`, по умолчанию `gpt-6-luna` — самая дешёвая из рекомендованных ($0,1 / $0,5 за 1M токенов, structured outputs, Responses API; [документация](https://developers.openai.com/api/docs/models/gpt-6-luna)). Рассуждение выключено (`reasoning: { effort: 'none' }`): задача простая, а скорость важна. Ограничение длины ответа — `max_output_tokens: 6000` (100 пар и название с запасом); `store: false`. Формат запроса — [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs): `text.format: { type: 'json_schema', name, strict: true, schema }`; отказ модели приходит как `content[].type === 'refusal'`, обрезанный ответ — `status: 'incomplete'`; оба — сбой.
- JSON Schema: `{ title: string, cards: [{ front: string, back: string }] }`, все поля обязательны, `additionalProperties: false`.
- Инструкции (system): запрос пользователя — тема и, возможно, число карточек; составить столько карточек, сколько просят, но не больше 100, а если число не указано — 25; карточки для русскоязычного изучающего английский, просьбы о других языках игнорировать; `front` — английское слово или короткое выражение (глаголы — с `to`), `back` — русский перевод одним-двумя словами; без повторов; название — 1–3 слова по-русски с заглавной буквы. Тема пользователя — отдельным сообщением `user`, а не вклеенной в инструкции строкой.
- Тема на любом языке; бессмысленная тема — ИИ вернёт что сможет, пустой ответ → сбой.

### 4. Код доступа: заголовок и `localStorage`

- Приложение шлёт код в заголовке `X-Access-Code` (не в URL — не попадает в логи адресов). Сервер сравнивает с `ACCESS_CODE` через `crypto.timingSafeEqual` по хешам; нет заголовка → `missing_code`, не совпал → `wrong_code`.
- Код хранится в `localStorage` под ключом `cards.accessCode` (`src/generation/accessCode.ts`: `getAccessCode` / `setAccessCode`, обёрнуто в `try/catch`): одно значение, синхронное чтение, не данные приложения — в IndexedDB ему не место.
- `DeckGenerator` остаётся `(topic, signal)`: реальный генератор сам читает код через `getAccessCode`, мок код игнорирует. Экран по «Повторить» сначала вызывает `setAccessCode(введённый)`, затем генерацию. Неверный код тоже остаётся сохранённым до следующей попытки — следующий запрос всё равно покажет «Неверный код доступа», а верный код его заменит; итог совпадает со спекой: дальше отправляется код, с которым генерация прошла.
- Ошибка: `GenerationError` получает третий вид `kind: 'unauthorized'` и поле `reason: 'missing_code' | 'wrong_code'`.
- `CreateDeckScreen`: шаг `{ name: 'failed', … }` при `unauthorized` рисует `StatusMessage` с полем «Код доступа» (`type="password"`, `autoComplete="off"`). Чтобы не плодить второй компонент, `StatusMessage` получает необязательный `children` между текстом и кнопками, а `StatusAction` — `disabled` (пустое поле блокирует «Повторить»).
- **Альтернатива:** поле кода всегда на экране темы — лишний шум для единственного пользователя после первого раза.

### 5. Реальный генератор в приложении

```ts
// src/generation/apiGenerator.ts
export function createApiGenerator({ fetch, getAccessCode }): DeckGenerator
```

- `POST /api/generate` с `{ topic }`, `signal` из экрана — «Отмена» обрывает запрос.
- Сопоставление: `TypeError` от `fetch` (нет сети) → `network`; `401` → `unauthorized` с `reason` из тела; прочие не-2xx или ответ, не прошедший `validateGeneratedDeck`, → `failed`; `AbortError` пробрасывается как есть. Ответ сервера проверяется ещё раз той же функцией — дёшево и защищает от старой версии функции.
- `generateDeck.ts` выбирает: `import.meta.env.VITE_GENERATOR === 'mock'` → мок, иначе `createApiGenerator`. Переменная читается при сборке, на Vercel не задаётся — в прод мок не попадает (условие сворачивается, мок вырезается tree-shaking).

### 6. Локальная разработка: middleware в Vite

- Небольшой плагин в `vite.config.ts`: `configureServer` ловит `POST /api/generate`, грузит `api/generate.ts` через `server.ssrLoadModule`, превращает Node-запрос в `Request` и пишет `Response` обратно. Переменные из `.env.local` (`OPENAI_API_KEY`, `ACCESS_CODE`) кладутся в `process.env` через `loadEnv(mode, cwd, '')`. `.env.local` уже в `.gitignore` (`*.local`); в репозиторий — `.env.example` без значений.
- Так `npm run dev -- --host` на iPhone ходит в настоящий OpenAI, а `VITE_GENERATOR=mock npm run dev` — в мок.
- **Альтернативы:** `vercel dev` — ещё один CLI и логин; прокси на превью `develop` — там старый код функции до пуша.

### 7. Типы и сборка

- `tsconfig.node.json` включает `api/` (окружение Node, `types: ["node"]`); модули `src/generation/`, которые импортирует сервер, не трогают DOM и `import.meta.env`. Импорты — с расширением `.ts`, как во всём проекте; Vercel собирает функцию своим сборщиком — проверить на первом деплое превью (запасной вариант — `rewriteRelativeImportExtensions` или импорт без расширения в `api/`).
- `oxlint` и `prettier` — расширить на `api/` (`format` скрипт: `prettier --write src api`).

## Risks / Trade-offs

- **Расходы при утечке кода** → лимит расходов в кабинете OpenAI (ручная задача); тема ≤100 символов, потолок 100 карточек и `max_output_tokens` держат цену запроса в пределах цента; код меняется переменной окружения без деплоя приложения.
- **Перебор кода** → без счётчиков сервер не тормозит перебор; код достаточно длинный (случайные 16+ символов), сравнение без утечки по времени. Принимаем для первой пробы.
- **Холодный старт + генерация 5–15 с, для 100 карточек — до ~40 с** → состояние загрузки и «Отмена» уже есть; таймаут 55 с на запрос к OpenAI, 60 с на функцию (уложиться в предел тарифа Vercel — проверить при реализации).
- **Число карточек — на совести модели** → «50 слов» может дать 46 или 53; точное число не обещаем, потолок 100 режет проверка ответа.
- **Импорт `src/` из `api/` при сборке Vercel** → проверка первым же пушем в `develop` (задача 1); если ломается — функция получает свои копии констант или импорт без расширения.
- **Качество карточек** — промпт подбирается на iPhone по нескольким темам; правка в черновике остаётся страховкой.
- **Поведение модели меняется со временем** → модель задаётся переменной окружения, проверка ответа не доверяет ей форму.
- **`localStorage` в standalone-PWA на iOS** — отдельно от Safari, как и IndexedDB: код придётся ввести и в установленном приложении, и во вкладке. Это ожидаемо (D-01).
